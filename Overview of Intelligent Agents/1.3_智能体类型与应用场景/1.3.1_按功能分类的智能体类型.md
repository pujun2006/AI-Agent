按功能与职责划分智能体（AI Agent），有助于在系统设计、多智能体编排和业务落地时明确各模块的边界。从**工程应用与系统架构职能**的视角，现代大模型驱动的智能体通常可分为以下 **八大核心功能类型**（同时在古典 AI 理论中也有从“决策机制复杂度”划分的经典五类，文末一并对照说明）。

### 一、 现代工程视角下的八大功能型智能体

#### 1. 规划与编排型智能体（Planner & Orchestrator Agent）

* **核心功能**：系统的“总指挥”。负责接收用户的复杂高层目标，将其拆解为有依赖关系的子任务序列或有向无环图（DAG），分配给下游专业智能体，并根据执行反馈动态调整后续计划。
* **关键能力**：任务分解（Task Decomposition）、优先级排序、异常处理与重规划（Re-planning）。
* **典型场景**：跨部门业务流自动化主控、复杂科研调研总控代理。

#### 2. 路由与分发型智能体（Router & Triage Agent）

* **核心功能**：系统的“交通枢纽”。对进入系统的请求进行快速意图识别、难度评估与安全合规预检，然后将其路由到最合适的模型、知识库或垂直子智能体，避免所有简单请求都消耗高成本强推理模型。
* **关键能力**：低延迟分类、上下文槽位提取、负载均衡与降级兜底。
* **典型场景**：企业级智能客服总入口（售前/售后/账单/技术分流）、大小模型动态调度器。

#### 3. 检索与知识管理型智能体（Retrieval & Research Agent）

* **核心功能**：专职的“信息侦察员”。不只是被动执行单次向量匹配，而是根据问题自主改写检索词、跨多源（内部文档库、SQL 数据库、图数据库、实时网页）进行多跳检索、去重交叉验证，并沉淀结构化记忆。
* **关键能力**：Agentic RAG、查询扩展、来源溯源与幻觉过滤。
* **典型场景**：深度行业研报助手、企业内部知识问答、法律与医疗文献综述代理。

#### 4. 工具执行与操作型智能体（Action & Execution Agent）

* **核心功能**：系统的“实干手”。专注于将推理意图转化为对外部软件、硬件或系统的精确操作，打通“最后一公里”执行闭环。
* **常见细分形态**：
* **API / 业务系统操作代理**：调用 CRM、ERP、邮件、日历等标准化接口完成读写。
* **电脑与浏览器操作代理（Computer Use / GUI Agent）**：通过识别屏幕截图或 DOM 树，模拟人类点击、输入、滚动来操作没有开放 API 的桌面或网页应用。
* **具身智能体（Embodied Agent）**：结合传感器与物理执行器，在真实物理空间中导航、抓取与交互（如机器人、自动驾驶车辆）。



#### 5. 代码与数据分析型智能体（Coding & Data Analysis Agent）

* **核心功能**：专职的“工程师与分析师”。能够在隔离沙箱中编写、运行、调试代码，查询数据仓库，完成精确统计计算、数据清洗、图表可视化甚至端到端软件开发。
* **关键能力**：代码生成与静态检查、沙箱运行反馈自修复、SQL 生成与数据洞察提炼。
* **典型场景**：仓库级软件工程代理（自动修 Bug、写单测、提 PR）、自动化 BI 数据分析助手。

#### 6. 评估、审查与安全护栏型智能体（Critic, Evaluator & Guardrail Agent）

* **核心功能**：系统的“质检员与风控官”。不直接对外输出最终业务动作，而是专门审查其他智能体的规划、代码、文本或工具调用参数是否准确、合规、安全。
* **关键能力**：自我反思打分（Self-Reflection）、事实一致性核查、提示词注入检测、敏感数据脱敏与高危操作拦截。
* **典型场景**：多智能体辩论中的“反方审查者”、内容合规审核网关、自动化测试用例验证代理。

#### 7. 记忆与状态管理型智能体（Memory & Context Agent）

* **核心功能**：系统的“档案管理员”。在长周期交互中持续提炼对话与任务轨迹中的关键事实、用户偏好和实体变化，负责短期上下文压缩、长期记忆写入、冲突消解与遗忘清理。
* **关键能力**：信息抽取与结构化沉淀、时间衰减管理、跨会话状态同步。
* **典型场景**：长期私人助理、个性化教育伴侣、持续演进的项目管理助手。

#### 8. 交互与多模态呈现型智能体（Interface & Companion Agent）

* **核心功能**：直接面向终端用户的“前台代言人”。负责统一对外话术风格、情感共情、多模态交互（语音实时对话、视觉理解）以及生成式动态 UI（图表、表单、卡片）的组装呈现。
* **关键能力**：人设一致性维持、交互式澄清引导、异步任务进度播报与人工确认（HITL）对接。
* **典型场景**：虚拟数字人客服、智能座舱语音助手、交互式学习导师。

### 二、 八大功能型智能体对比总览

| 功能类型 | 核心定位 | 主要输入与输出 | 典型技术抓手 |
| --- | --- | --- | --- |
| **规划编排型** | 任务拆解与全局调度 | 高层目标 → 子任务 DAG / 调度指令 | 思维链规划、状态机、动态重规划 |
| **路由分发型** | 意图识别与流量分发 | 原始请求 → 目标路由标签 / 槽位参数 | 轻量分类模型、语义路由、规则网关 |
| **检索研究型** | 多源信息获取与核实 | 信息需求 → 经核验的证据摘要与引用 | Agentic RAG、查询改写、多跳检索 |
| **工具执行型** | 外部系统与物理交互 | 结构化动作指令 → API/GUI/物理执行结果 | Function Calling、MCP、浏览器/GUI 自动化 |
| **代码分析型** | 编程开发与精确计算 | 需求/数据集 → 可运行代码、分析报告与图表 | 沙箱代码解释器、AST 解析、SQL 引擎 |
| **评估审查型** | 质量校验与安全风控 | 候选方案/动作 → 通过/驳回决策与修改建议 | Critic 评分、规则护栏、红队对抗检测 |
| **记忆管理型** | 经验沉淀与状态维护 | 交互轨迹 → 结构化长期记忆 / 压缩上下文 | 向量库、知识图谱、摘要压缩管道 |
| **交互呈现型** | 用户沟通与界面适配 | 内部执行结果 → 自然语言、语音或动态 UI | 多模态理解、生成式 UI、HITL 确认流 |

### 三、 补充视角：经典 AI 理论中的五类智能体（按决策机制划分）

如果在学术或架构设计中遇到从“内部决策机制复杂度”出发的经典分类（源自《人工智能：一种现代的方法》），它与上述功能分类是正交互补的，可快速对照理解：

1. **简单反射型（Simple Reflex Agent）**：仅依据当前瞬时感知触发预设规则（`If-Then`），无记忆、无规划，适合高频确定性路由与基础安全拦截。
2. **基于模型的反射型（Model-Based Reflex Agent）**：在内部维护对环境状态和演化规律的模型，能处理部分可观测环境（如跟踪任务当前处于哪一步）。
3. **基于目标型（Goal-Based Agent）**：不仅知道当前状态，还明确“目标状态”，会主动搜索和规划达成目标的行动序列（当前绝大多数任务型 LLM Agent 属于此类）。
4. **基于效用型（Utility-Based Agent）**：当存在多条路径都能达成目标时，通过效用函数权衡**成本、延迟、成功率与风险**，选择综合收益最优的方案。
5. **学习型智能体（Learning Agent）**：内置评估器与学习组件，能够从历史成功/失败轨迹、用户反馈或强化学习奖励中持续优化自身策略与记忆库。

在实际的企业级多智能体系统（Multi-Agent System）中，单一智能体往往难以兼顾所有职责，最成熟的实践是将上述不同功能型智能体**模块化组合**——例如以“路由型”接入口，由“规划型”拆解任务，并行调动“检索型”“代码分析型”与“工具执行型”干活，最后经由“评估审查型”把关并由“交互呈现型”交付给用户。
