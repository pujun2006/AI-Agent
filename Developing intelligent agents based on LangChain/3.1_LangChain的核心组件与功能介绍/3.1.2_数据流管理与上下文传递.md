LangChain 的**数据流管理**与**上下文传递**以 LCEL（LangChain 表达式语言）的 `Runnable` 协议为基础设施，将单次调用内的数据变换、跨节点字段保留与跨轮次状态持久化解耦为清晰的声明式机制。

## 一、数据流管理：声明式管道与结构化契约

在 LCEL 体系中，数据在各组件之间以标准 Python 对象（尤其是字典与消息列表）单向或分叉流动，而非依赖早期隐式的全局内存字典：

* **强契约驱动的 Schema 校验：** 每个 `Runnable` 节点都暴露 `input_schema` 与 `output_schema` 属性，明确声明自身接收和产出的数据结构。上游节点的输出必须匹配下游提示模板或函数的预期字段名，否则需要通过映射节点进行显式桥接。
* **扇出分发与键值聚合（`RunnableParallel`）：** 面对多路数据加工（如同时提取多个字段或并行检索多个数据源），字典字面量或 `RunnableParallel` 会将同一份上游输入同步分发给多个子链，待所有分支完成后按预设键名合并为新的字典输出，避免手动拼接中间变量的命令式样板代码。
* **数据清洗与字段提取（`RunnableLambda` / `itemgetter`）：** 利用 `itemgetter` 从上游字典中精准抽取所需键传入下一节点，或通过 `RunnableLambda` 嵌入类型转换、格式校验与字段重命名逻辑，保证管道各环节的数据形态纯净可控。
* **增量流式穿透（Streaming Propagation）：** 数据流不仅支持整包传递（`invoke` / `batch`），还支持增量块传播（`stream` / `astream`）。只要中间变换节点不阻塞全量缓冲，上游大模型生成的 Token 即可逐块穿过后续解析器直达终端。

## 二、上下文传递的三层机制

随着链路变长或进入多轮对话，单纯的“前一步输出覆盖后一步输入”会导致原始问题、检索证据或历史记录丢失。LangChain 通过三个层级解决上下文传递问题：

### 1. 链内单次执行上下文保留（`RunnablePassthrough` 与 `.assign()`）

* **原样透传（`RunnablePassthrough()`）：** 充当恒等信使，在并行结构中将上游原始输入原封不动地带入下一阶段（例如在 RAG 中同时保留用户原始 `question` 与检索得到的 `context`）。
* **无损增量扩充（`RunnablePassthrough.assign(...)`）：** 在不覆盖现有输入字典的前提下，并行计算新字段并合并回原字典。例如输入 `{"question": "..."}` 经过 `.assign(context=...)` 后，输出自动变为 `{"question": "...", "context": [...]}`，实现不可变数据流中的状态累积。

### 2. 运行时元上下文注入（`RunnableConfig`）

* 业务元数据（如 `user_id`、`session_id`、权限令牌、追踪标签或超时设置）不应混入提示词业务字段中。
* LangChain 通过调用时传入的 `RunnableConfig` 沿整条执行树隐式向下透传运行时配置；任意自定义 `RunnableLambda` 或工具只需在签名中声明 `config` 参数即可读取这些上下文，实现业务数据与运行环境的彻底隔离。

### 3. 跨轮次与跨节点持久化上下文（History 与 State Graph）

* **会话历史管理（`RunnableWithMessageHistory`）：** 包装基础链后，系统依据 `config` 中的 `session_id` 在每次调用前自动拉取历史消息列表注入提示词占位符，并在生成完成后自动将本轮问答追加写入外部存储（如 Redis、PostgreSQL），配合窗口截断或摘要压缩控制上下文长度。
* **全局状态机与上下文裁剪（LangGraph State & Context Scoping）：** 在复杂多步工作流或智能体循环中，上下文升级为带归约器（Reducer）的强类型共享状态（State）；调度器在调用具体子任务时按需映射局部字段，确保每个节点仅接触完成当前步骤所需的最小上下文，防止无关历史干扰模型注意力。

## 三、上下文传递方式对照

| 上下文范围 | 核心机制 | 数据形态 | 典型应用场景 |
| --- | --- | --- | --- |
| **相邻节点直传** | `|` 管道 + `itemgetter` | 单一值或扁平字典 | 提示词填充、模型输出提取纯文本 |
| **链内多步累积** | `RunnablePassthrough.assign` | 键值不断扩充的字典 | 多阶段推理、RAG 检索片段与原问题合并 |
| **运行环境元数据** | `RunnableConfig` | 配置字典（与业务载荷分离） | 传递用户 ID、会话标识、链路追踪与回调标签 |
| **跨轮次对话记忆** | `RunnableWithMessageHistory` | 结构化 `BaseMessage` 序列 | 多轮客服助手、带历史追问的知识库问答 |
| **复杂工作流状态** | LangGraph 共享 State | 带更新规则的状态对象 | 多智能体协作、循环工具调用、断点人工审批 |
