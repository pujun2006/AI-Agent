Sequential chain task scheduling.py代码演示了一个典型的 **LCEL 多步串行任务链**，将“问题解析”与“后续步骤生成”拆解为两个串联阶段，并接入了阿里云通义千问（`ChatTongyi`）聊天模型。

---

## 分段解析

### 1. 依赖导入与环境变量加载

* **`load_dotenv()`**：从当前目录或父级目录的 `.env` 文件读取键值对注入系统环境变量，避免在源码中硬编码密钥。
* **`ChatTongyi`**：来自 `langchain_community.chat_models`，用于对接阿里云 DashScope 通义千问对话接口。
* **`PromptTemplate` 与 `StrOutputParser**`：来自 `langchain_core`，前者定义带占位符的文本提示模板，后者将模型返回的 `AIMessage` 提取为纯字符串（`str`）。

### 2. 模型初始化

```python
llm = ChatTongyi(
    model=os.getenv("LLM_MODEL_ID"),
    dashscope_api_key=os.getenv("LLM_API_KEY"),
    temperature=0.7,
)

```

* 从环境变量读取模型标识（`LLM_MODEL_ID`）与 API 密钥（`LLM_API_KEY`）。
* 设置 `temperature=0.7`，在保证回答结构清晰的同时保留一定发散度，适合“解析问题”与“规划后续步骤”这类生成任务。

### 3. 提示模板定义

* **`template_1`**：接收 `{"question": ...}`，输出 `"解析问题: {question}"`，负责先拆解或梳理用户问题。
* **`template_2`**：接收 `{"answer": ...}`，输出 `"基于答案：{answer}，生成后续步骤"`，负责承接第一阶段结果并延展出可执行的下一步行动。

### 4. LCEL 任务链编排

```python
chain = (
    template_1
    | llm
    | StrOutputParser()
    | (lambda text: {"answer": text})
    | template_2
    | llm
    | StrOutputParser()
)

```

整条链路按数据流向分为两段：

1. **第一阶段（问题解析）：** `{"question": "..."}` 传入 `template_1` 生成提示文本 → `llm` 推理生成消息对象 → `StrOutputParser()` 转为纯文本 `str`。
2. **字段映射适配：** `(lambda text: {"answer": text})` 充当桥梁。因为 `StrOutputParser()` 输出的是 `str`，而 `template_2` 期望字典输入 `{"answer": ...}`，若缺少这一步键名转换，后续模板填充会报错。
3. **第二阶段（生成后续步骤）：** 映射后的字典传入 `template_2` → 再次调用 `llm` 生成后续步骤 → `StrOutputParser()` 输出最终纯文本结果。

### 5. 同步调用与输出

`chain.invoke({"question": "如何实现机器学习模型的训练？"})` 以同步方式触发整条链路执行，并将最终生成的后续步骤字符串打印到控制台。

## 实践细节与潜在改进点

* **输入键名与模板对齐：** `template_1` 声明了 `input_variables=["question"]`，因此 `invoke` 传入的字典必须包含 `"question"` 键。
* **显式包装 `RunnableLambda`：** 代码中直接写了 `(lambda text: {"answer": text})`，LCEL 会自动将其 coercion 为 `RunnableLambda`；显式写成 `RunnableLambda(lambda text: {"answer": text})` 在复杂链路中可读性与调试体验更好。
* **保留原始问题上下文：** 当前链路只把第一阶段输出作为 `answer` 传给 `template_2`；若希望第二阶段同时看到原始 `question`，可在第一阶段外层使用 `RunnablePassthrough.assign(...)` 拼接字段，而不是覆盖原有字典。
* **环境依赖提示：** 运行前需安装 `langchain-core`、`langchain-community`、`dashscope` 与 `python-dotenv`，并在 `.env` 中配置有效的 `LLM_MODEL_ID` 和 `LLM_API_KEY`。
