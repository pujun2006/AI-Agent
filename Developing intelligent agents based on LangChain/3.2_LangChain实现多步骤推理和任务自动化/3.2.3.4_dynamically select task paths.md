ynamically select task paths.py代码实现了一个“客户画像读取 + 全局 LLM 响应缓存 + LCEL 条件动态路由”的投资策略生成工作流。它会根据 `client_id` 拉取客户投资偏好，通过 `RunnableBranch` 路由到短期或长期策略子链，并借助全局缓存复用相同请求的模型输出。

---

### 一、 核心组件与执行流程

整个流程分为缓存与数据源初始化、策略子链构建、条件动态路由、异步主流程四个阶段：

1. **环境变量与全局 LLM 缓存（`InMemoryCache`）**
* `load_dotenv()` 读取 `.env` 中的 `LLM_MODEL_ID` 与 `LLM_API_KEY`。
* `langchain.llm_cache = InMemoryCache()` 开启进程级内存缓存。当后续遇到完全相同的提示词与模型参数组合时，可直接命中缓存返回结果，减少重复推理耗时与费用。


2. **客户偏好查询函数（`query_client_preferences`）**
* 从内存字典 `CLIENT_DB` 中按 `client_id` 查询客户信息（`name`、`client_type`、`risk_level`）。
* 若传入未知 ID，则返回默认兜底字典（`name="未知客户"`、`client_type="长期投资"`、`risk_level="低"`）。


3. **多策略 LCEL 子链（`short_term_strategy_chain`、`long_term_strategy_chain`、`default_chain`）**
* 三条链均采用 `PromptTemplate | llm | StrOutputParser()` 结构，分别面向 1-3 个月短期对冲/套利、3-5 年核心-卫星资产配置，以及标准平衡策略。
* 提示词直接引用 `client_info` 字典中的 `{name}` 与 `{risk_level}` 字段进行个性化渲染。


4. **条件动态路由与异步编排（`strategy_router_branch` 与 `process_client_investment_plan`）**
* `RunnableBranch` 按 `client_type` 精确匹配 `"短期投资"` 或 `"长期投资"`，其余情况落入 `default_chain`。
* `process_client_investment_plan` 先调用 `query_client_preferences(client_id)` 获取客户属性，再通过 `await strategy_router_branch.ainvoke(client_info)` 异步执行匹配到的策略链。
* `main()` 分别验证 `CLI-001`（短期投资路由）与 `CLI-002`（长期投资路由）的完整输出。

### 三、 潜在风险与改进点

* **全局缓存键与版本兼容风险：** 在较新的 `langchain_core` 版本中，全局缓存通常建议通过 `from langchain_core.globals import set_llm_cache` 设置，并注意缓存键依赖模型名称、参数与完整 prompt；若未来修改了 prompt 模板但未清理缓存，可能返回旧模板对应的结果。
* **内存缓存无法跨进程与跨重启：** `InMemoryCache` 和 `CLIENT_DB` 均驻留在当前进程内存中，服务重启会清空缓存，多进程部署也无法共享。生产环境可替换为 `SQLiteCache` / `RedisCache` 以及真实数据库查询。
* **多余导入与业务边界：** 代码导入了 `RunnableLambda` 但未显式调用；此外，投资策略生成属于高敏感金融场景，实际落地时需注意合规提示、输入校验以及对未知客户 ID 的显式风控处理（当前未知客户会直接按“低风险长期投资”生成方案）。
