Asynchronous task chain execution.py这段代码展示了一种典型的“先并行拆解、后串行汇总”（Fan-out / Fan-in）任务分解模式，利用 LangChain 的 `RunnableParallel` 与异步接口 `ainvoke`，将包含多类金融需求的复合问题拆分为相互独立的专项分析，最后再合并生成综合方案。

---

## 一、 整体执行拓扑与耗时特征

整条链路 `full_chain = parallel_chain | summary_chain` 的数据流转如下：

```text
{"query": "我想借款 10 万块买车，顺便办一张适合消费刷卡的信用卡"}
       │
       ├──────────────────────────────────────┐
       ▼                                      ▼
chain_loan (贷款专家分析)              chain_credit (信用卡专家分析)
       │                                      │
       └──────────────────┬───────────────────┘
                          ▼  合并为字典
         {"loan_analysis": "...", "credit_analysis": "..."}
                          │
                          ▼  summary_chain (串行汇总生成)
                    最终综合金融服务方案

```

* **并发优势**：相比串行先等贷款分析完成、再等信用卡分析开始，`RunnableParallel` 会同时发出两路请求，第一阶段的耗时取决于较慢的一支，而不是两支之和。
* **角色分工**：把单次提示词里容易“顾此失彼”的多意图拆成两个角色视角的子链，各自聚焦单一领域。

## 二、 逐段代码解析

### 1. 异步运行库与环境初始化

```python
import os
import asyncio
from dotenv import load_dotenv
...
load_dotenv()

llm = ChatTongyi(
    model=os.getenv("LLM_MODEL_ID", "qwen-max"),
    dashscope_api_key=os.getenv("LLM_API_KEY"),
    temperature=0.7
)

```

* 引入 `asyncio` 是为了在 `main()` 中通过 `await full_chain.ainvoke(...)` 驱动异步并发执行。
* `temperature=0.7` 保留了一定创造力，适合撰写方案建议类文本；若后续接入严格规则校验或结构化抽取，通常可调低至 `0.0–0.3`。

---

### 2. 独立子任务链构建（`chain_loan` 与 `chain_credit`）

```python
prompt_loan = PromptTemplate.from_template("作为贷款专家，分析以下问题中的贷款需求：{query}")
prompt_credit = PromptTemplate.from_template("作为信用卡专家，分析以下问题中的信用卡需求：{query}")

chain_loan = prompt_loan | llm | StrOutputParser()
chain_credit = prompt_credit | llm | StrOutputParser()

```

* 两条子链结构完全一致：**提示词模板 → 大语言模型 → 字符串解析器**。
* 两者互不依赖，各自接收顶层输入的 `query` 变量，输出各自的文本分析结果。

---

### 3. 并行分发节点（`RunnableParallel`）

```python
parallel_chain = RunnableParallel(
    loan_analysis=chain_loan,
    credit_analysis=chain_credit
)

```

* `RunnableParallel` 会把相同的输入字典广播给 `loan_analysis` 和 `credit_analysis` 两个分支。
* 执行完毕后，它会把各分支的结果组装成一个新字典返回，键名即参数名：`{"loan_analysis": ..., "credit_analysis": ...}`。

---

### 4. 串行汇总节点与总链拼接

```python
summary_prompt = PromptTemplate.from_template(
    "结合以下两方面的分析结果，为客户生成一份综合金融服务方案：\n"
    "1. 贷款分析：{loan_analysis}\n"
    "2. 信用卡分析：{credit_analysis}"
)
summary_chain = summary_prompt | llm | StrOutputParser()

full_chain = parallel_chain | summary_chain

```

* `summary_prompt` 声明了 `{loan_analysis}` 和 `{credit_analysis}` 两个占位符，正好与 `parallel_chain` 输出字典的键一一对应，因此无需额外写字典映射函数即可直接串联。
* 最终 `full_chain` 形成“双路并行 → 单路汇总”的组合链。

---

### 5. 异步调用入口

```python
async def main():
    print("🚀 开始并行请求通义千问 API...")
    res = await full_chain.ainvoke({"query": "我想借款 10 万块买车，顺便办一张适合消费刷卡的信用卡"})
    print("\n👉 最终综合响应：\n", res)

if __name__ == "__main__":
    asyncio.run(main())

```

* 调用 `ainvoke` 而非同步 `invoke`，才能让底层异步链路真正并行调度多个协程任务；最后通过 `asyncio.run(main())` 启动事件循环。

## 四、 工程实践中的可改进点

1. **变量名兼容检查**：代码中读取的是 `os.getenv("LLM_API_KEY")`；若你的 `.env` 配置的是 `DASHSCOPE_API_KEY`，建议加上兜底逻辑（`os.getenv("DASHSCOPE_API_KEY") or os.getenv("LLM_API_KEY")`）并做非空校验。
2. **明确业务合规边界**：车贷与日常消费信用卡涉及资金用途合规与授信审核，在金融场景下可在 `prompt_loan`、`prompt_credit` 或 `summary_prompt` 中补充“不构成审批承诺、资金用途需合规”等约束。
3. **复杂多分支升级**：如果后续不仅要并行分析，还要根据分析结果做条件跳转、多轮重试或维护复杂状态，可考虑迁移到 `LangGraph` 的图编排模式。
