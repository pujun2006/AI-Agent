Scheduled task execution.py代码将 **LCEL 顺序处理链** 与 **APScheduler 定时调度器** 结合，实现了一个**定时自动生成的金融业务日报工作流**。整体逻辑分为“数据提取 → 日报撰写 → 定时触发”三部分。

---

### 一、 核心模块与执行流程

1. **环境与模型初始化**
* `load_dotenv()` 从 `.env` 读取 `LLM_MODEL_ID` 和 `LLM_API_KEY`。
* `ChatTongyi` 初始化通义千问模型（默认 `qwen-max`），`temperature=0.7` 用于保留一定文案表达与排版灵活性（相比前一段路由代码的 `0.1` 更高）。


2. **两阶段顺序 LCEL 链（`daily_report_chain`）**
* **第一阶段（指标提取）：** `template_extract | llm | StrOutputParser()` 接收 `{"raw_data": ...}`，让模型扮演金融分析师提炼核心业务指标与摘要，并输出字符串。
* **变量对齐转接：** `(lambda summary_text: {"summary": summary_text})` 把上一阶段的字符串输出包装成字典，以匹配下一阶段 `template_report` 的 `{summary}` 占位符。
* **第二阶段（日报生成）：** `| template_report | llm | StrOutputParser()` 基于摘要生成结构化、带后续建议的正式日报文本。


3. **定时任务函数（`generate_daily_report_job`）**
* 每次触发时先准备业务数据（当前为 `mock_data` 模拟消费贷申请、通过率、放款额与坏账率），再调用 `daily_report_chain.invoke({"raw_data": mock_data})` 执行流水线。
* 通过 `try...except` 捕获调用或网络异常，避免单次执行出错导致整个调度进程崩溃。


4. **阻塞式定时调度器（`BlockingScheduler`）**
* `BlockingScheduler()` 会占用当前主线程循环等待任务触发，适合作为独立的后台定时脚本运行。
* 当前启用的是 `'interval'`（每 30 秒执行一次）用于联调测试；注释掉的 `'cron'` 示例（`hour=8, minute=0`）适合生产环境每天 08:00 定时跑批。
* 捕获 `KeyboardInterrupt` / `SystemExit`，便于按 `Ctrl+C` 或接收停止信号时安全退出。

### 三、 实际落地时的改进建议

* **替换模拟数据为真实数据源：** 在 `generate_daily_report_job` 中接入数据库查询、BI 接口或文件读取，并建议加入**数据为空/异常时的兜底判断**，防止空数据误触发大模型生成假报告。
* **增加输出投递动作：** 日报生成后通常不只是 `print`，可在 Job 末尾补充写入 Markdown/PDF 文件、发送企业微信/邮件/飞书通知，或存入数据库归档。
* **警惕 `BlockingScheduler` 的线程与并发细节：**
* `BlockingScheduler` 会阻塞主线程；如果后续要在 FastAPI/Web 服务中复用，需改用 `BackgroundScheduler` 或 `AsyncIOScheduler`。
* 若日报生成耗时超过间隔周期（例如任务耗时 40 秒但间隔设成 30 秒），建议显式配置 `max_instances=1`、`coalesce=True` 和 `misfire_grace_time`，防止任务重叠堆积。


* **生产环境建议升级持久化与重试：** 本地脚本重启后内存中的调度状态不会保留；若涉及关键金融报表或高可靠任务，可进一步考虑 Celery Beat、Airflow 或带持久化 JobStore 的调度方案。
